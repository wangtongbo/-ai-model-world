# 多语言改造规范（zh / en / ja / ko）

> 本文档是多语言改造的**契约**。所有参与改动的代码必须遵守这里的约定。
> 背景与不可违背的原则见 `docs/HANDOFF.md`（数据诚信、合规红线、零 AI 依赖全部照旧）。

## 决策记录（产品负责人已确认）

| 决策点 | 结论 |
|---|---|
| URL 结构 | 根路径保持中文不变；新增 `/en/`、`/ja/`、`/ko/` 前缀镜像站 |
| 非中文版视频入口 | 「评测视频」改为 YouTube 搜索 `{模型名} review`；B 站视频列表区块在非中文版**不渲染** |
| 非中文版页脚 | 简化：作者署名 + 源码链接 + 数据/素材出处；**不放** B 站引流、中文教程、中文导航按钮 |
| 榜单名/厂商名 | 各语言统一用英文原名（SWE-bench Verified、OpenAI、Alibaba…）；说明文字翻译 |
| 「国外/国内」概念 | 非中文版按读者视角译为 Global / China（west→Global, east→China） |

## 核心 API（`src/lib/i18n/`）

```ts
export const LANGS = ['zh', 'en', 'ja', 'ko'] as const;
export type Lang = (typeof LANGS)[number];
export const DEFAULT_LANG: Lang = 'zh';
export function isLang(s: string): s is Lang;

/** 多语言文本。zh/en/ja/ko 四键齐全，tsc 强制；缺一门语言编译不过。 */
export type LText = Record<Lang, string>;
export function lt(text: LText, lang: Lang): string;   // 取值，兜底 en → zh

export function htmlLang(lang: Lang): string;           // zh-CN / en / ja / ko
export function langPrefix(lang: Lang): string;         // zh→'' 其余→'/en' 等
export function langLink(lang: Lang, href: string): string; // 站内链接加前缀
```

字典分文件，统一由 `src/lib/i18n/index.ts` 组装：

| 文件 | 归属 | 内容 |
|---|---|---|
| `core-dict.ts` | 已有 | 站名/导航/广场/类型/状态/页脚等（原 i18n.ts 的内容） |
| `lib-dict.ts` | lib 层 | persona / aptitude / champions / traits / 搜索概念 / 对比 insights / 日期格式化 |
| `ui-dict.ts` | 组件层 | components 里抽出的所有文案 |
| `pages-dict.ts` | 页面层 | 各页面专属文案（时间线、对比、排行榜、详情、厂商、credits） |

每个文件导出 `XxxDict` interface 和 `export const xxxDict: Record<Lang, XxxDict>`。
**新增 key 时必须四语言一次写全**——`Record<Lang, …>` 会让漏写的语言直接编译报错。

## 路由（静态导出，一次构建产出全部语言）

- `src/app/**` 保持不动 = 中文版（根路径）。
- 新增 `src/app/[lang]/`，`generateStaticParams` 返回 `[{lang:'en'},{lang:'ja'},{lang:'ko'}]`，**`export const dynamicParams = false`**。
- 页面正文抽成共享组件 `src/components/pages/<X>Page.tsx`，签名为 `{ lang: Lang }`（详情页另带 slug 等参数）。根路径页面变成薄壳：`export default function Page() { return <HomePage lang="zh" /> }`。
- `[lang]/model/[slug]/` 的 `generateStaticParams` 返回 lang × slug 笛卡尔积（复用现有的 slug 列表逻辑）。
- `[lang]/layout.tsx`：用 `generateMetadata` 产出该语言的 title/description；渲染 `<SetHtmlLang lang={lang} />`（客户端小组件，effect 里设 `document.documentElement.lang`——静态导出下嵌套 layout 改不了根 `<html>`，这是约定俗成的做法）。
- `/qa/crests/` 是开发校验页，**不做**多语言，不进 `[lang]`。
- metadata 里给 `alternates.languages` 指到各语言对应路径（含 x-default → 根路径中文版）。

## 链接规则（最容易漏）

- **所有站内 `<a href>` / 跳转必须过 `langLink(lang, href)`**。中文版输出与现状完全一致。
- 锚点链接（`#champions`）不加前缀。站外链接不加前缀。
- 静态资源（精灵图、`/search-index.json`、`/compare-data.json`）走原有 `asset()`，**不加**语言前缀。
- 客户端组件（GlobalSearch、LeaderboardExplorer、CompareView）内部拼链接同样过 `langLink`。
- `useUrlQuery` 只改 query string，不动路径，无需改。

## 各模块改造要点

### lib 层（签名保持向后兼容，新增 `lang` 参数）

- `persona.ts`：`superlative`、`prefix`、`PRICE_WORDS`、`MEMORY_WORDS`、`CONTEXT_ANCHORS`、
  `positioning()` 模板、兜底句全部抽成 per-lang 查表放进 `lib-dict.ts`。
  语法模板（如 `${domain.prefix}${dim.superlative}的模型`）做成字典函数：
  `persona.champion(domain, superlative)` / `persona.positioning(...)`，因为四种语言语序不同。
  `personaFor(model, ctx, lang: Lang = 'zh')`。
- `aptitude.ts` / `champions.ts` / `traits.ts`：标签与悬停文案同样处理。
- `format.ts`：`formatDate` 等按 lang 输出（zh「2026 年 9 月」/ en「Sep 2026」/ ja「2026年9月」/ ko「2026년 9월」）。价格、数字格式不变。
- `search.ts`：`CONCEPTS` 改为 per-lang 词表（每种语言一张表，词不同、指向的筛选参数相同）。
  索引结构 `SearchIndex` 加 `concepts: Record<Lang, …>`；`runSearch(index, raw, lang)`。
  `matchesConcept` 与 `filters.ts` 的 `makePredicate` 同义这条铁律不变（见 HANDOFF 搜索一节）。
- `compare.ts`（数据构建）：`persona` 字段从 `string` 改为 `LText`（四种语言一次算好），
  单一 `/compare-data.json` 保持不变，体积可接受。
- `compare/insights.ts`：所有判断文案函数加 `lang` 参数。

### data 层（纯增量字段，不破坏现有结构）

- `vendor-registry.ts`：`VendorProfile` 增加 `nameEn: string`（国际通用名，如 `Zhipu AI`、`Moonshot AI`）。
  新增 `vendorName(profile, lang)`：zh→nameZh，其余→nameEn。
- `coding-leagues.ts`：league 增加 `nameEn`；`description` 改为 `LText`。
  榜单原名本身就是英文，`nameEn` 用上游官方名。
- `benchmark-registry.ts`：`BenchmarkInfo` 增加 `nameEn`；一句话说明改 `LText`；
  分类名（BENCHMARK_CATEGORIES）改 `LText`。
- `official-scores.ts`：榜单 league 名的多语言处理与 coding-leagues 同步。

### 组件层

- 所有硬编码中文抽进 `ui-dict.ts`。组件已经收 `lang` prop 的沿用；没收的补上。
- `ReviewLinks`：zh 保持 B 站 + 鱼皮导航；en/ja/ko 渲染 YouTube 搜索链接
  （`https://www.youtube.com/results?search_query=${encodeURIComponent(name + ' review')}`），
  不渲染「评测文章」链接。
- `VideoList`：`lang !== 'zh'` 时**不渲染**（数据全是中文 B 站视频）。
- `BiliLink`：不动（非中文版根本到不了这里）。
- `SiteFooter`：zh 现状；非中文版渲染简化版（署名 + 源码 + credits 链接）。
- `SiteNav`：加语言切换器（`LangSwitcher`，客户端组件，`usePathname` 算目标地址，
  保留 query string）。zh 页面也显示，方便切出去。

### 页面层

- 每个页面抽共享组件时，把页面级中文（标题、说明、空态、表格表头）抽进 `pages-dict.ts`。
- `chronicle` 页的年月分组标题、`credits` 页全文都要四语言。
- 日期显示统一走 `format.ts` 的 lang 版本，不要在页面里手拼「X 年 Y 月」。

## 禁区（从 HANDOFF 继承，多语言语境下的具体化）

1. **不调用任何 LLM/翻译 API**：所有翻译是写死在字典里的人工翻译，与「零 AI 依赖」一致。
2. 数据诚信不变：en/ja/ko 的「暂无数据」「未参评」等措辞要与中文一样精确，不得美化。
3. 合规红线不变：任何语言版本都不出现 AA 数据；外链政策一致。
4. 中文版（根路径）的渲染输出**逐字节不变**是第一目标——所有改动对 zh 必须是恒等变换。
5. 不改 `src/lib/types.ts` 的数据契约（管线产出不动）；多语言只发生在展示层与注册表增量字段。
